Part 1

Why Solana Chose UDP Over TCP

Solana processes millions of transactions per second. Every packet matters. The protocol choice at the transport layer shapes everything above it: how validators gossip, how blocks propagate, how your transaction reaches the leader.

01

The Fundamental Question

Every networking textbook starts with TCP. It's reliable. It handles retransmissions. It guarantees ordering. TCP powers the web, email, SSH, databases. It's the safe default.

So why does Solana, a blockchain processing millions of transactions and propagating blocks to thousands of validators around the planet, use UDP as its primary transport?

The answer isn't "UDP is faster." That's a half-truth at best. The real answer is about what TCP costs at validator scale, and why those costs are unacceptable for a system that needs to produce a block every 400 milliseconds.

02

TCP vs UDP: The Core Difference

TCP
Connection-oriented
  • 3-way handshake before any data flows
  • Per-connection state: buffers, sequence numbers, congestion window
  • Guaranteed in-order delivery
  • Automatic retransmission on packet loss
  • Congestion control: slow start, AIMD
UDP
Connectionless
  • No handshake. Send immediately.
  • One socket receives from any source
  • No per-peer state in the kernel
  • No ordering guarantees
  • No retransmission. Fire and forget.
Real-World Analogy

TCP is certified mail. You send a letter, wait for delivery confirmation, then send the next one. Every letter is tracked, every delivery is verified, and the post office throttles you if you send too fast.

UDP is a firehose. You blast data out. The receiver catches what they can. No receipts, no waiting, no throttling.

03

Why TCP Fails at Validator Scale

TCP's guarantees aren't free. Each one comes with overhead. At the scale a Solana validator operates, that overhead compounds into a showstopper.

TCP: 2,000 peer connections
2,000 sockets with send/recv buffers,
congestion windows, timer state
UDP: 1 socket, all peers
1 socket handles every peer.
Zero per-connection kernel state.

Connection State Overhead

A validator talks to 2,000+ peers. TCP needs a socket plus kernel memory per connection: send/recv buffers, congestion window, timers. That's massive memory and CPU spent on bookkeeping instead of processing transactions.

~26KB kernel memory per socket

Head-of-Line Blocking

If one TCP segment is lost, the entire stream stalls until retransmission completes. Transactions are independent. Transaction A should never block Transaction B. At 1M+ packets per second, even 0.1% loss means thousands of stalls per second.

0.1% loss at 1M pps = 1,000 stalls/sec

Congestion Control Fights You

TCP's slow start and AIMD actively throttle throughput. A validator during its leader slot wants to saturate the network, blasting shreds to the entire cluster as fast as possible. TCP says "slow down" at exactly the wrong moment.

AIMD: halve window on any loss

In-Order Delivery Is Wasted

Transactions are independent units. There's no ordering dependency between them. TCP pays the cost of maintaining sequence numbers and reordering buffers for zero benefit. It's overhead with no upside.

Cost paid, benefit = 0
04

Solana's Four UDP Consumers in Agave

UDP isn't used the same way everywhere in the validator. Agave has four distinct subsystems that consume UDP, each with different requirements. Click any card to see implementation details.

01 Raw UDP

Gossip & Repair

Gossip is how validators discover each other and share cluster state: contact info, vote timestamps, epoch data. Repair is how validators request missing shreds from peers. Both use classic raw UDP sockets. Many-to-many broadcast pattern. Opening QUIC connections to every peer would be prohibitively expensive.

Protocol: custom Solana gossip protocol over raw UDP datagrams. Pattern: many-to-many fan-out. Code: agave/gossip/src/ + agave/core/src/repair/

02 QUIC over UDP

Transaction Ingress (TPU)

The TPU (Transaction Processing Unit) uses QUIC (RFC 9000) for client transaction submission. QUIC gives per-stream flow control, TLS 1.3 auth, and stake-weighted rate limiting. But from the kernel's perspective, QUIC doesn't exist. The kernel just sees UDP datagrams. All QUIC logic runs in userspace via the quinn Rust crate.

QUIC: connection state + crypto in userspace (quinn crate). Kernel sees: plain UDP port 8004 datagrams. Enables: stake-weighted QoS, TLS 1.3 identity.

03 Shred UDP

Turbine Shreds

Block propagation. The leader shreds a block into ~1,232-byte pieces with Reed-Solomon erasure coding, then fans them out through a tree of validators. This is the most latency-critical UDP path in the entire system. Every millisecond of delay increases fork risk.

Shred size: ~1232 bytes (fits in one UDP datagram). Erasure coding: Reed-Solomon FEC for loss tolerance. Tree structure: stake-weighted, multi-layer fan-out.

04 Internal

Streamer Layer

Agave's internal abstraction layer. Reads packets from sockets via recvmmsg, groups them into PacketBatch (a Vec of 128 packets), then sends batches through crossbeam channels to downstream pipeline stages: sigverify, dedup, banking.

recvmmsg: batch syscall, reads multiple packets in one call. PacketBatch: Vec<Packet>, typically 128 packets. Channel: crossbeam bounded MPSC to sigverify stage.

05

Reliability Without TCP

Dropping TCP doesn't mean accepting chaos. Solana builds reliability at the application layer, where each subsystem can choose exactly the guarantees it needs without paying for ones it doesn't.

Idempotent Transactions

Every transaction includes a recent blockhash and a unique signature. If a duplicate arrives, the validator's dedup table catches it. Lost in transit? The client just resubmits. No harm done.

Erasure Coding (Turbine)

Turbine uses Reed-Solomon coding on block shreds. A validator can reconstruct a complete block even when a significant fraction of shreds are lost in transit. The math handles what TCP retransmission would.

QUIC Where It Matters

For client-to-validator transaction submission, QUIC adds selective reliability on top of UDP. Per-stream flow control, TLS 1.3 authentication, and connection migration. The cost is paid only where the benefit exists.
