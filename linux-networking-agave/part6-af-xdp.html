the Kernel Entirely

XDP filters bad packets before the kernel sees them. AF_XDP eliminates the kernel path for good packets too. This is the full kernel bypass.

01

The Culmination

Part 5 showed XDP attaching eBPF programs at the NIC driver, before the kernel allocates a single sk_buff. With XDP_DROP, spam packets vanish at line rate. With XDP_PASS, legitimate traffic still flows through the kernel's full networking stack.

That is half the story. Dropping bad traffic is necessary, but for a Solana validator processing millions of packets per second, the kernel stack is still the bottleneck for good traffic. The protocol parsing, socket lookup, queue management, buffer copies, and syscalls from Parts 2 and 3 all apply to every packet that passes through.

AF_XDP closes the loop. It creates a shared-memory channel between the NIC and your application. Packets land in memory that userspace already owns. No kernel data structures. No copies. No syscalls on the hot path.

02

What AF_XDP Is

AF_XDP (Address Family XDP) is a socket type, also called XSK (XDP Socket). It creates a shared memory channel between the NIC driver and userspace. The key idea: packets the NIC writes via DMA are the same bytes the application reads. No intermediate copies. No kernel data structures on the critical path.

  1. 1 Userspace allocates UMEM, a large contiguous memory region for packet frames
  2. 2 UMEM is registered with the kernel and NIC driver
  3. 3 NIC's DMA writes packets directly into UMEM buffers
  4. 4 XDP program redirects packets to the AF_XDP socket via XDP_REDIRECT
  5. 5 Userspace reads packet data from UMEM: no copy, the data is already there
The core insight

The packet bytes the NIC DMA'd are the same bytes the application reads. Zero copies. Zero sk_buff allocations. Zero syscalls on the data path.

03

UMEM: The Shared Memory Region

UMEM is a pre-allocated pool of packet-sized frames. It is the foundation of AF_XDP's zero-copy design. The same physical memory pages are mapped into both kernel and userspace address spaces. Two virtual addresses, one set of physical pages.

  • Contiguous memory, mmap'd by userspace at startup
  • Divided into equal-sized frames, typically 4096 bytes each
  • Mapped into both kernel and userspace address spaces simultaneously
  • Same physical pages, two virtual mappings: this is what makes zero-copy possible
  • For a validator: ~8192 frames = 32MB UMEM
  • Allocated once at startup, never freed during operation

04

The Four Rings

AF_XDP replaces the kernel's socket queues, spinlocks, and syscalls with four lock-free ring buffers. Each ring is SPSC (single-producer, single-consumer). One side writes, one side reads. No locks needed: memory barriers (atomic operations) handle synchronization at ~5-10ns versus a spinlock's 200-1000ns under contention.

05

AF_XDP Objects

Four components make up the AF_XDP machinery. Together they replace the entire kernel socket subsystem for the traffic that needs maximum throughput.

XSK (XDP Socket)
AF_XDP socket bound to a specific network device and hardware queue. The entry point for the bypass path.
UMEM
Userspace-owned packet frame memory registered with the kernel. The shared buffer pool both sides read and write.
RX / FILL Rings
Userspace supplies free frames via FILL. Kernel returns received packet descriptors via RX. The inbound data path.
TX / COMPLETION Rings
Userspace submits frames to send via TX. Kernel reports completions. The outbound data path.

07

Zero-Copy vs Copy Mode

AF_XDP supports two modes of operation. The difference is where the NIC's DMA writes packet data. Both modes are dramatically faster than the classic kernel path, but zero-copy removes the last remaining copy.

Optimal
Zero-Copy Mode
NIC DMAs directly into UMEM frames. The DMA buffer is the UMEM frame. No copy at any stage. This is the fastest possible path: NIC writes, application reads, same physical memory.
Requires driver support: mlx5, ice, i40e, ixgbe
Fallback
Copy Mode
Kernel copies from the driver's DMA buffer into UMEM. One memcpy. Still avoids sk_buff allocation, protocol stack, netfilter, and syscalls. Much faster than classic.
Fallback for unsupported drivers. Still skips steps 7-14.
Comparison

Even copy mode is a massive win over the classic path. The classic path pays for sk_buff allocation, IP parsing, UDP demux, netfilter, socket lookup, queue spinlock, recvmsg, and copy_to_user. Copy-mode AF_XDP pays for one memcpy. Everything else is gone.

08

Full vs Selective Bypass

Not all traffic needs kernel bypass. SSH connections need the kernel's TCP stack. Gossip runs at low enough rates that the classic path handles it fine. The power of AF_XDP combined with XDP is selective: each packet class gets the right treatment.

Pragmatic
Selective Bypass
XDP classifies each packet. High-throughput streams get XDP_REDIRECT to AF_XDP. Low-rate or TCP-dependent traffic gets XDP_PASS to the normal stack. Spam gets XDP_DROP.
Used by: Agave (what a production validator would do)

Full Bypass

The Architecture

Three zones, two paths. The XDP + eBPF layer sits at the driver level and makes the routing decision for every packet. Redirected packets go straight to userspace through shared memory. Everything else flows through the normal kernel stack.
