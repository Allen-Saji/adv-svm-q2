The Core Tradeoff

Every step right on this table trades generality for speed. Classic UDP works with any NIC, any kernel config, any firewall. AF_XDP needs driver support, dedicated memory, custom parsing. Pick the layer that matches your performance requirement.

02

How XDP + eBPF Shape Modern I/O

XDP is not just a Solana optimization. It is now the standard interface between Linux and high-performance hardware. The same pattern (early programmable hooks, kernel bypass, zero-copy) appears in every modern I/O subsystem.

I/O Drivers
XDP is the standard way modern NIC drivers are built. Mellanox mlx5, Intel ice/igc, AMD all expose an early eBPF hook inside the RX path. Vendors build XDP support directly into driver firmware and DMA rings for zero-copy, low-latency I/O.
Packet Schedulers
Linux Traffic Control now attaches eBPF programs (BPF_PROG_TYPE_SCHED_CLS, BPF_PROG_TYPE_SCHED_ACT) directly to queueing disciplines. Fully programmable, stateful packet schedulers (FQ, Cake) that run at line-rate without leaving the driver.
CPU / SoftIRQ Schedulers
NAPI polling + XDP turns the old interrupt-driven model into a cooperative scheduler. The kernel decides when to poll, and XDP lets you steer or drop packets before they reach the softIRQ scheduler.
The General Pattern
Same architecture everywhere: early programmable hooks (eBPF/XDP) + kernel bypass (AF_XDP, io_uring) + zero-copy. This is the foundation for all high-performance networking, storage, and tracing in modern kernels.

Agave Code Pointers

The patterns from this series map directly to real code in the Agave validator. These are the entry points for anyone reading the codebase. Each card shows the function chain and the file where the hot path lives.

streamer.rs #L160
Batched UDP receive. recv_loop calls packet::recv_from which fans out to recv_mmsg for batch reception.
recvmmsg.rs #L94
Linux recvmmsg. Builds mmsghdr / iovec arrays and calls libc::recvmmsg to receive multiple UDP packets in a single syscall.
sendmmsg.rs #L208
Batched UDP send. batch_send routes through sendmmsg helpers to transmit multiple packets per syscall on the egress path.
agave-xdp-prog.rs #L18
XDP program. agave_xdp is the eBPF entrypoint attached at the NIC driver level. Parses headers, checks allowlists, returns DROP or REDIRECT.
xdp/socket.rs #L45
AF_XDP setup. Socket, UMEM, and ring configuration. This is where the validator allocates shared memory and binds to specific NIC queues for zero-copy reception.
quic_socket.rs #L31
AF_XDP egress. QUIC socket support for AF_XDP-backed sending. Bypasses the kernel on the transmit path for transaction data flowing back to the network.

06

Key Takeaways

01
Filter early, bypass where possible
The same principle as Solana's sigverify stage. Validate cheap properties first, reject early, only invest heavy resources on packets that pass. XDP DROP costs nanoseconds. A full kernel traversal costs microseconds.
02
The kernel is not the enemy
The kernel path is general, compatible, and observable. You bypass it where performance demands it, not everywhere. Agave's selective bypass is easier to maintain and debug than a full bypass. Use the right tool for each traffic class.
03
This pattern is universal
Early hooks + kernel bypass + zero-copy is the pattern for all modern high-performance I/O. io_uring does the same for storage. The same principles apply to any system processing millions of operations per second.
